## Phase 0

- Owner: switch Settings → Pages → Source to "GitHub Actions" before merging to `main` (otherwise the old branch deploy keeps running and `/schema/` stays missing).
- Root `npm test`: 3 failures locally come from an untracked `tools/.DS_Store` (Finder file); not present in a clean checkout.

## Phase 1
- Model (`src/model/`): types, zod schema with defaults, migration entry (v1), stable serializer (one component per line), topology rules (`validate.ts`).
- Renderer (`src/render/render.ts`): pure SVG string, used by CLI and editor. Frame (ISO 5457 margins), title block template, legend of used media, flow arrows, medium code at the start of each medium run, crossing bridges.
- Router (`src/layout/route.ts`): A* on the sheet grid with bend/crossing/overlap costs; waypoints are taken as given.
- CLI: `validate`, `render` (PNG via resvg with the bundled Plex fonts, or SVG), `new --template empty|ahu-basic`.
- Tests: validation cases, migration errors, serializer round trip, geometry, symbol rules, PNG reference per example (`tests/visual/`).

## Phase 2
- 29 symbols (`examples/symbol-catalog.schema`): all ventilation symbols of the plan + junction. Norm PDFs present locally (EN 12792, SIA 411, EN 1861, EN ISO 10628-2, EN 806-1, IEC 81346-1/-2); EN 12792 symbols checked against it, own symbols marked "*".
- Strand layout (`src/layout/auto.ts`), A* routing with bridges, sheet fitting (gap shrink + size suggestion), drawing check.
- Operations (`src/ops/ops.ts`) and `cli ops` / `notes` / `resolve` (the latter two ahead of phase 5).
- Examples (generated by `scripts/make-examples.ts`): einfache Zu-/Abluft, Monoblock Platten-WRG, Monoblock Rotor + Erhitzer + Kühler, KVS-System, VVS 3 Zonen. All valid, 0 drawing warnings, PNG references in `tests/visual/`.
- Open: automatic row wrapping on overfull sheets (see DECISIONS), media check of `insert_into_connection` against the new component's ports.

## Phase 3
- Editor (`src/editor/`): own SVG canvas showing the renderer's output plus an interaction layer. Zoom (wheel), pan (middle button or Space + drag), fit (0).
- Palette with search (names, IDs, keywords), drag & drop or click (places in the middle of the view). Dropping on a line inserts the symbol into it, turned along the line (one undo step).
- Connect by dragging port to port (medium from the neighbouring lines or the first allowed one; from → to follows the flow when started at an input). Move with grid snap; moved components get pinned, lines follow, manual routes of lines with one moved end are reset. Drag a line segment to set waypoints.
- Selection: click, Shift + click, rectangle, Ctrl+A; groups (Ctrl+G, select by frame, moving moves members).
- Properties panel (label, props incl. own ones, rotation, mirror, pinned; line medium, direction, automatic routing; sheet and title block), notice list (topology + drawing check), warning marks on the sheet.
- Undo/redo with Immer patches, 200 steps; an external reload is one step (used in phase 4). Shortcuts: see help dialog (?).
- Open via file input, save as download (Ctrl+S), SVG export, examples menu, browser draft (localStorage) so a reload keeps the work.
- Tests: Vitest 100, Playwright 4 (build 6 components by mouse → save → reopen → identical file; undo/redo; insert into a line; rectangle selection, group, duplicate, delete). `npm run test:e2e` builds and serves `dist/` itself.
- Fixed on the way: Ctrl+S saved a stale document (keyboard handler kept an old state); file input "cancel" fired before "change" in Chromium.
- Open: text items can be edited but not created in the UI yet (only via file/ops); note tool comes in phase 5.

## Phase 4
- File System Access API (`src/io/fsa.ts`, `session.ts`): open and save in place (Ctrl+S, Ctrl+Shift+S save as), last file remembered in IndexedDB; on start it reopens directly if permission is still granted, else a banner offers «Wieder öffnen» (permission needs a click).
- Live sync: polling every second (`lastModified`, then content). No local edits → reload as one undo step with a message, view and selection kept. Unsaved edits → dialog «Externe Version laden», «Meine behalten (überschreiben)», «Beide als Kopie». Invalid/half-written file → banner with the error line, retried every second. Own writes are not taken as external changes. Optional autosave 2 s after the last edit (toolbar, only with an open file).
- Other browsers: file input + download, a one-time hint that live sync needs Chrome or Edge.
- Export menu: PDF (vector, sheet size 1:1, Plex embedded, text as text), SVG, PNG 300 dpi (fonts embedded). jsPDF/svg2pdf load only on PDF export.
- E2E (10 total): reload within 2 s after the test writes the file, half-written file, conflict (both choices), Ctrl+S into the file, PDF 420 × 297 mm with extractable text and no raster images, SVG/PNG (4961 × 3508 px). The live-sync tests use real file handles of the origin private file system; the native pickers cannot be automated.
- Not tested automatically: the native open/save pickers and the permission prompt after a browser restart (manual check in Chrome).

## Phase 5
- Note tool (toolbar, `N`, Esc ends it): click a component, a line or a free spot → text field at the click; Enter saves (`add_note`, one undo step), then back to the select tool with the note open.
- Pins are clickable (hit circles in the editor overlay) and open the note in the new «Anmerkungen» tab: filter open/done/all, text and reply editable, jump to the spot (view centred on the pin), done/reopen, delete. Each change is one undo step. Pin number now centred in the pin head.
- Deleting a component or line turns its notes into free notes at the same spot (editor and `remove` op), see DECISIONS.
- Exports never contain pins (unit test on `renderSchema` and `exportSvgText`).
- Fixed: Escape in a property field committed the edit instead of cancelling it.
- Tests: Vitest 106, Playwright 12 (place a note by mouse → saved into the live file → resolved with the CLI logic written into the file → editor shows «erledigt» after live sync; pin click, status, delete, undo).
