# PDF-Editor: decisions

Decisions taken while working through [PLAN.md](PLAN.md) (owner, 2026-10-19) where the plan left a choice open or a stage needed a workaround. One entry each: decision, reason, how to change it.

## Stage 1: EmbedPDF spike

- **E1 Vendored files: only what the snippet entry reaches.** `scripts/vendor-embedpdf.mjs` copies the module graph of `dist/embedpdf.js` (static and dynamic imports, worker and wasm URLs: 64 modules, 2 workers, 1 wasm, 16.1 MB) instead of the whole `dist/`. Reason: the other entries (`index.js`, `portable.js`, `core.js`) import bare npm specifiers and cannot run without a bundler; copying them adds dead files. Change: replace the graph walk with a copy of every non-map file in `dist/`.
- **E2 Package download without `npm pack`.** The script fetches the same tarball from the npm registry and checks its `dist.integrity` (sha512), then unpacks it in memory (`scripts/npm-package.mjs`). Reason: no dependency on the npm CLI or `tar` (Windows, Git Bash), same bytes as `npm pack`. Change: none needed; `npm pack` gives the identical file.
- **E3 Colour swatches by patch.** The annotation style panel has a fixed swatch list and no setting for it. The vendor script patches the one constant to `globalThis.HLKS_ANNOT_SWATCHES ?? [original]`; the changed file carries a notice (Apache-2.0 section 4b) and `lib/vendor/embedpdf/PATCHES.md` lists it. The page sets the global from `--annot-*` in `tokens.css` before it loads the viewer. Change: remove the `patch('swatches', …)` call; the viewer then shows its own swatches, the tool defaults (stage 2) still use ours.
- **E4 Swiss German viewer strings are generated.** The 16 German viewer strings with ß are overridden through the `strings` option. `scripts/vendor-embedpdf.mjs` writes them to `tools/pdf-editor/viewer-strings.js` (ß → ss); `tests/pdf-editor.vendor.test.js` fails when an update brings a new one. Own wording changes go to `labels.js`.
- **E5 Spike export kept as a fixture.** The spike placed every annotation type, three measurements after calibration, a stamp from an imported PDF library and two form fields through the viewer API, saved with `documents.download()` (incremental) and reopened in Node. The file is `tests/fixtures/pdf-editor/embedpdf-annotated.pdf`; the vendor test checks it with MuPDF (no repair, every subtype, cloudy border, page scale `/VP /Measure`) and pdf-lib. It does not test a newer EmbedPDF by itself; repeat the spike after an update (TODO-OWNER).
- **E6 v3 passes; no fallback to v2.** Acceptance met: no request outside the site (checked in the browser network log, also under `serve.mjs --base Tools-HLKS-WEB`), export reopens without repair, measurement after calibration exact (140 pt calibrated as 5000 mm: distance 5000.00 mm, area 12.5 m²).
- **E7 Findings for stage 2.** (a) Free text uses Helvetica with WinAnsi: `Δ` and `≤` are kept in the text but missing in the regenerated appearance after reopening. IBM Plex Sans is registered as the viewer font and made the default for text tools. (b) Measurement labels use English number format (`5,000.00 mm`); see the stage 2 entries.
- **E8 Sub-path dev server.** `.claude/launch.json` got `hlks-tools-subpath` (`serve.mjs 8083 --base Tools-HLKS-WEB`) for the preview pane.
