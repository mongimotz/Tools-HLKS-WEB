# PDF-Editor: decisions

Decisions taken while working through [PLAN.md](PLAN.md) (owner, 2026-10-19) where the plan left a choice open or a stage needed a workaround. One entry each: decision, reason, how to change it.

## Stage 1: EmbedPDF spike

- **E1 Vendored files: only what the snippet entry reaches.** `scripts/vendor-embedpdf.mjs` copies the module graph of `dist/embedpdf.js` (static and dynamic imports, worker and wasm URLs: 64 modules, 2 workers, 1 wasm, 16.1 MB) instead of the whole `dist/`. Reason: the other entries (`index.js`, `portable.js`, `core.js`) import bare npm specifiers and cannot run without a bundler; copying them adds dead files. Change: replace the graph walk with a copy of every non-map file in `dist/`.
- **E2 Package download without `npm pack`.** The script fetches the same tarball from the npm registry and checks its `dist.integrity` (sha512), then unpacks it in memory (`scripts/npm-package.mjs`). Reason: no dependency on the npm CLI or `tar` (Windows, Git Bash), same bytes as `npm pack`. Change: none needed; `npm pack` gives the identical file.
- **E3 Colour swatches by patch.** The annotation style panel has a fixed swatch list and no setting for it. The vendor script patches the one constant to `globalThis.HLKS_ANNOT_SWATCHES ?? [original]`; the changed file carries a notice (Apache-2.0 section 4b) and `lib/vendor/embedpdf/PATCHES.md` lists it. The page sets the global from `--annot-*` in `tokens.css` before it loads the viewer. Change: remove the `patch('swatches', …)` call; the viewer then shows its own swatches, the tool defaults (stage 2) still use ours.
- **E4 Swiss German viewer strings are generated.** The 16 German viewer strings with ß are overridden through the `strings` option. `scripts/vendor-embedpdf.mjs` writes them to `tools/pdf-editor/viewer-strings.js` (ß → ss); `tests/pdf-editor.vendor.test.js` fails when an update brings a new one. Own wording changes go to `labels.js`.
- **E5 Spike export kept as a fixture.** The spike placed every annotation type, three measurements after calibration, a stamp from an imported PDF library and two form fields through the viewer API, saved with `documents.download()` (incremental) and reopened in Node. The file is `tests/fixtures/pdf-editor/embedpdf-annotated.pdf`; the vendor test checks it with MuPDF (no repair, every subtype, cloudy border, page scale `/VP /Measure`) and pdf-lib. It does not test a newer EmbedPDF by itself; repeat the spike after an update (TODO-OWNER).
- **E6 v3 passes; no fallback to v2.** Acceptance met: no request outside the site (checked in the browser network log, also under `serve.mjs --base Tools-HLKS-WEB`), export reopens without repair, measurement after calibration exact (140 pt calibrated as 5000 mm: distance 5000.00 mm, area 12.5 m²).
- **E7 Findings for stage 2.** (a) Free text uses Helvetica with WinAnsi: `Δ` and `≤` are kept in the text but missing in the regenerated appearance after reopening. IBM Plex Sans is registered as the viewer font and made the default for text tools. (b) Measurement labels use English number format (`5,000.00 mm`); see the stage 2 entries.
- **E8 Sub-path dev server.** `.claude/launch.json` got `hlks-tools-subpath` (`serve.mjs 8083 --base Tools-HLKS-WEB`) for the preview pane.

## Stage 2: page shell

- **S1 Theme through CSS, not a config object.** The viewer reads `--epdf-*` set on its host element before its own defaults (`:host { --embedpdf-host-*: var(--epdf-*) }`). `style.css` maps them to our tokens, so Hell / Dunkel follow without JavaScript; `theme.js` only switches the viewer's light/dark preference (its internal shades). The plan's "theme config (light + dark)" is therefore not built. Change: pass `theme: { tokens, dark }` in `viewerConfig()` instead.
- **S2 Viewer chrome mapping.** background and surface → `--surface`, canvas → `--surface-sunken` (paper on a sunken well, like PDF → DXF), raised → `--surface`, hover → `--surface-hover`, radius → `--r-button`, font → `--font-sans`.
- **S3 Annotation colours.** Okabe-Ito with a stronger red (`#d42a20`): the plan asks for red, blue, green, yellow, black, orange, magenta, cyan; this set keeps every pair at CIEDE2000 ≥ 10 under protan and deutan simulation (minimum 11.6, yellow/orange). White is a ninth swatch for whiteout and outside the check. They are document colours, defined once in `:root` (no dark variant). Change: edit `--annot-*` in `tokens.css` and the table in `dragon-ink.md`; the test re-checks.
- **S4 Undo / redo in the app bar.** The shared rule puts ↶ ↷ in every app bar, so the viewer's undo/redo groups are removed from its mode bars; the buttons run the viewer's `history:undo` / `history:redo` and follow their enabled state (`viewer.watch`). Change: drop the `remove(['history:undo', …])` loop in `editLayout()`.
- **S5 Shortcuts in the capture phase.** The viewer binds Mod+O, Mod+S, Mod+Z, Mod+Y itself. The page handles them on `window` in the capture phase and stops them, so each runs exactly once with the page's open/save (original file name). Strg+Z / Strg+Y inside text fields stay native. The viewer's `document:open` and `document:download` commands are overridden to the same functions.
- **S6 Page editing as an own viewer mode.** The page-edit plugin has an API but no buttons. A mode `Seiten` (layout `addBar`) adds rotate left/right, blank page after, duplicate, move forward/back, delete for the current page. These edits are not in the viewer's undo history (EmbedPDF limit); deleting a page extracts it first and offers undo in its toast (shared rule "Deletion offers undo"). The other page edits undo themselves (rotate back, move back, delete the inserted page).
- **S7 Own tools.** `Revisionswolke` (polygon with cloudy border intensity 1, markup red, 1 pt) in the Formen bar and `Abdecken` (white square without border, white fill) in the Schwärzen bar, defined with the annotation plugin's `extends`.
- **S8 Text annotations in IBM Plex Sans.** The PDF subsets in `assets/fonts/pdf/` cover German, French, Italian and `° ² ³ ± Ø Δ ≤ ≥ ’` (checked with MuPDF), so no subset change was needed. They are registered as engine fonts and set as the free-text and callout default; text survives save and reopen with all glyphs. Free text has no frame (plan labels); callouts keep a red frame.
- **S9 Swiss measurement format.** The page scale's number formats carry the thousands and decimal separators (`/RT`, `/RD`). The default scale is written with `’` and `.`, and `bridge.js` rewrites any owned scale after calibration or a preset (`onScaleChanged` → `setScale`, guarded so it runs once). Result: `5’000.00 mm`, `12’500’000.76 mm²`.
- **S10 Password prompt and damaged files.** The viewer has its own password dialog (`Kennwort erforderlich`); the notice row shows the same neutral status. A file PDFium cannot read shows the viewer's error view and `PDF nicht lesbar` in the notice row. PDFium does not repair a cut-off file that MuPDF can repair; a repair through the MuPDF worker is part of stage 4.
- **S11 One document at a time.** Tabs are hidden (`tabs('never')`); opening a file replaces the open one. Autosave (stage 6) keeps unsaved work.
- **S12 Settings draft without `DocumentStore`.** The editor's history is the viewer's; settings have no undo, so they are a plain `localStorage` entry normalised by `normalizeSettings`.
- **S13 Registry test.** A duplicate registry line slipped in during this stage; `tests/registry.test.js` now checks unique ids, pages and tile icons.
