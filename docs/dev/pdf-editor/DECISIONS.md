# PDF-Editor: decisions

Decisions taken while working through [PLAN.md](PLAN.md) (owner, 2026-10-19) where the plan left a choice open or a stage needed a workaround. One entry each: decision, reason, how to change it.

## Stage 1: EmbedPDF spike

- **E1 Vendored files: only what the snippet entry reaches.** `scripts/vendor-embedpdf.mjs` copies the module graph of `dist/embedpdf.js` (static and dynamic imports, worker and wasm URLs: 64 modules, 2 workers, 1 wasm, 16.1 MB) instead of the whole `dist/`. Reason: the other entries (`index.js`, `portable.js`, `core.js`) import bare npm specifiers and cannot run without a bundler; copying them adds dead files. Change: replace the graph walk with a copy of every non-map file in `dist/`.
- **E2 Package download without `npm pack`.** The script fetches the same tarball from the npm registry and checks its `dist.integrity` (sha512), then unpacks it in memory (`scripts/npm-package.mjs`). Reason: no dependency on the npm CLI or `tar` (Windows, Git Bash), same bytes as `npm pack`. Change: none needed; `npm pack` gives the identical file.
- **E3 Colour swatches by patch.** The annotation style panel has a fixed swatch list and no setting for it. The vendor script patches the one constant to `globalThis.HLKS_ANNOT_SWATCHES ?? [original]`; the changed file carries a notice (Apache-2.0 section 4b) and `lib/vendor/embedpdf/PATCHES.md` lists it. The page sets the global from `--annot-*` in `tokens.css` before it loads the viewer. Change: remove the `patch('swatches', …)` call; the viewer then shows its own swatches, the tool defaults (stage 2) still use ours.
- **E4 Swiss German viewer strings are generated.** The 16 German viewer strings with ß are overridden through the `strings` option. `scripts/vendor-embedpdf.mjs` writes them to `tools/pdf-editor/viewer-strings.js` (ß → ss); `tests/pdf-editor.vendor.test.js` fails when an update brings a new one. Own wording changes go to `labels.js`.
- **E5 Spike export kept as a fixture.** The spike placed every annotation type, three measurements after calibration, a stamp from an imported PDF library and two form fields through the viewer API, saved with `documents.download()` (incremental) and reopened in Node. The file is `tests/fixtures/pdf-editor/embedpdf-annotated.pdf`; the vendor test checks it with MuPDF (no repair, every subtype, cloudy border, page scale `/VP /Measure`) and pdf-lib. It does not test a newer EmbedPDF by itself; repeat the spike after an update (TODO-OWNER).
- **E6 v3 passes; no fallback to v2.** Acceptance met: no request outside the site (checked in the browser network log, also under `serve.mjs --base Tools-HLKS-WEB`), export reopens without repair, measurement after calibration exact (140 pt calibrated as 5000 mm: distance 5000.00 mm, area 12.5 m²).
- **E7 Findings for stage 2.** (a) Free text uses Helvetica with WinAnsi: `Δ` and `≤` are kept in the text but missing in the regenerated appearance after reopening. IBM Plex Sans is registered as the viewer font and made the default for text tools. (b) Measurement labels use English number format (`5,000.00 mm`); see the stage 2 entries.
- **E8 Sub-path dev server.** `.claude/launch.json` got `hlks-tools-subpath` (`serve.mjs 8083 --base Tools-HLKS-WEB`) for the preview pane.

## Stage 2: page shell

- **S1 Theme through CSS, not a config object.** The viewer reads `--epdf-*` set on its host element before its own defaults (`:host { --embedpdf-host-*: var(--epdf-*) }`). `style.css` maps them to our tokens, so Hell / Dunkel follow without JavaScript; `theme.js` only switches the viewer's light/dark preference (its internal shades). The plan's "theme config (light + dark)" is therefore not built. Change: pass `theme: { tokens, dark }` in `viewerConfig()` instead.
- **S2 Viewer chrome mapping.** background and surface → `--surface`, canvas → `--surface-sunken` (paper on a sunken well, like PDF → DXF), raised → `--surface`, hover → `--surface-hover`, radius → `--r-button`, font → `--font-sans`.
- **S3 Annotation colours.** Okabe-Ito with a stronger red (`#d42a20`): the plan asks for red, blue, green, yellow, black, orange, magenta, cyan; this set keeps every pair at CIEDE2000 ≥ 10 under protan and deutan simulation (minimum 11.6, yellow/orange). White is a ninth swatch for whiteout and outside the check. They are document colours, defined once in `:root` (no dark variant). Change: edit `--annot-*` in `tokens.css` and the table in `dragon-ink.md`; the test re-checks.
- **S4 Undo / redo in the app bar.** The shared rule puts ↶ ↷ in every app bar, so the viewer's undo/redo groups are removed from its mode bars; the buttons run the viewer's `history:undo` / `history:redo` and follow their enabled state (`viewer.watch`). Change: drop the `remove(['history:undo', …])` loop in `editLayout()`.
- **S5 Shortcuts in the capture phase.** The viewer binds Mod+O, Mod+S, Mod+Z, Mod+Y itself. The page handles them on `window` in the capture phase and stops them, so each runs exactly once with the page's open/save (original file name). Strg+Z / Strg+Y inside text fields stay native. The viewer's `document:open` and `document:download` commands are overridden to the same functions.
- **S6 Page editing as an own viewer mode.** The page-edit plugin has an API but no buttons. A mode `Seiten` (layout `addBar`) adds rotate left/right, blank page after, duplicate, move forward/back, delete for the current page. These edits are not in the viewer's undo history (EmbedPDF limit); deleting a page extracts it first and offers undo in its toast (shared rule "Deletion offers undo"). The other page edits undo themselves (rotate back, move back, delete the inserted page).
- **S7 Own tools.** `Revisionswolke` (polygon with cloudy border intensity 1, markup red, 1 pt) in the Formen bar and `Abdecken` (white square without border, white fill) in the Schwärzen bar, defined with the annotation plugin's `extends`.
- **S8 Text annotations in IBM Plex Sans.** The PDF subsets in `assets/fonts/pdf/` cover German, French, Italian and `° ² ³ ± Ø Δ ≤ ≥ ’` (checked with MuPDF), so no subset change was needed. They are registered as engine fonts and set as the free-text and callout default; text survives save and reopen with all glyphs. Free text has no frame (plan labels); callouts keep a red frame.
- **S9 Swiss measurement format.** The page scale's number formats carry the thousands and decimal separators (`/RT`, `/RD`). The default scale is written with `’` and `.`, and `bridge.js` rewrites any owned scale after calibration or a preset (`onScaleChanged` → `setScale`, guarded so it runs once). Result: `5’000.00 mm`, `12’500’000.76 mm²`.
- **S10 Password prompt and damaged files.** The viewer has its own password dialog (`Kennwort erforderlich`); the notice row shows the same neutral status. A file PDFium cannot read shows the viewer's error view and `PDF nicht lesbar` in the notice row. PDFium does not repair a cut-off file that MuPDF can repair; a repair through the MuPDF worker is part of stage 4.
- **S11 One document at a time.** Tabs are hidden (`tabs('never')`); opening a file replaces the open one. Autosave (stage 6) keeps unsaved work.
- **S12 Settings draft without `DocumentStore`.** The editor's history is the viewer's; settings have no undo, so they are a plain `localStorage` entry normalised by `normalizeSettings`.
- **S14 Shared drop handling.** `enableFileDrop` (`lib/core/files.js`) now leaves a drop alone when a drop zone on the page called `preventDefault()` (it still resets its overlay). The editor's Symbole panel uses it for SVG files; other pages are unchanged.
- **S13 Registry test.** A duplicate registry line slipped in during this stage; `tests/registry.test.js` now checks unique ids, pages and tile icons.

## Stage 3: symbols, stamps, signatures

- **Y1 Own SVG renderer instead of MuPDF's.** The vendored MuPDF.js build has no SVG document handler (`cannot find document handler for file type: 'image/svg+xml'`), so the plan's "SVG → PDF page via MuPDF" is not possible. `svg-render.js` draws the common SVG subset into PDF content operators (no DOM, no dependency), and `svg.js` assembles the page with MuPDF (fonts, transparency, images). Our symbols and stamp templates stay inside the subset; user SVGs from drawing programs mostly do too (paths, shapes, transforms, `<style>` classes). Left out: clip paths, masks, filters, patterns, gradients (first stop colour), text on paths. Change: if a later MuPDF.js build includes SVG, replace `renderSvg` in `svgToPdf` with `Document.openDocument(svg, 'image/svg+xml')` and a `DocumentWriter`.
- **Y2 Text in stamps with IBM Plex Sans.** `doc.addFont()` embeds Plex as a Type0 font with Identity encoding (CID = glyph id) and a ToUnicode map; text strings are glyph ids, so `Ø Δ ≤ ’ ä` render and stay searchable. `subsetFonts()` keeps the library small.
- **Y3 One library per symbol category.** The viewer groups stamps by library, so `scripts/build-symbol-library.mjs` writes `symbols/lueftung.pdf`, `heizung.pdf`, `sanitaer.pdf`, `allgemein.pdf` instead of one `symbols.pdf`, plus `libraries.json`. Their kind is `symbols`, so the viewer's library chooser in the Stempel panel lists only stamps; its "Alle Stempel" view still shows every asset (EmbedPDF behaviour, not configurable).
- **Y4 Symbole panel as own viewer panel, Stempel in the viewer's panel.** The viewer's stamp panel shows libraries well (library chooser, previews, PDF import), so there is no own Stempel panel (the plan's condition). Symbols get an own panel (`layout.addPanel('symbols')`, light DOM content) because they need SVG drop, delete with undo, and save/open of the own library. After a symbol is armed, an overlay panel closes, so one click places it.
- **Y5 Persistence by the viewer.** EmbedPDF already keeps every imported or created library (own symbols, signatures, our generated ones) in IndexedDB `embedpdf-stamps`. `library.js` does not keep a second copy; it waits for the viewer's restore before checking its own libraries (first version imported in parallel and created duplicates), removes copies, and skips the import when the `src:` fingerprint matches.
- **Y6 Empty own library.** A library saved without assets comes back from the viewer's store with one blank Letter page (`Stamp1`). The own library is therefore created with the first symbol, deleted when its last symbol goes, and a restored blank one is removed.
- **Y7 Stamp library drawn at runtime.** Name, date and own stamps change, so the `Stempel` library is drawn in the worker from `stamps/*.svg` on start (the date of the day) and after a settings change. Its fingerprint covers templates, settings, date and colours.
- **Y8 Viewer standard stamps off.** They are drawn in Helvetica with their own colours; the plan's stamps replace them (`stamp.standard: false`).
- **Y9 Signatures without typed marks.** `signature.fonts: []` removes the typing tab (only Plex is allowed and a typed Plex signature has no value); draw and upload stay. No signing key is configured, so a mark in a signature field is drawn, not cryptographically sealed.
- **Y10 Symbol drawings.** Drawn after common practice (fan as a circle with the triangle of lines, dampers across a duct, valves as bow-ties, check valve with bar, heater/cooler with + / −, north arrow, level mark, revision triangle). `norm` names the reference family (SN EN 12792 / DIN 1946-1, SIA 410 / DIN 2481, SN EN 806-1 / SVGW W3, SIA 400). The owner reviews them (TODO-OWNER).
- **Y11 Settings apply live.** Tool defaults are re-registered (`annotation.tools.register`), measurement presets updated (`updateSettings`); no new viewer mount, so the open document stays.

## Stage 4: document tools

- **D1 Insert pages through the viewer.** `PDFs anhängen` and `Bilder als Seiten` (into the open file) use the viewer's `pageEdit.insertFromBytes`, so the open document keeps its annotations and undo history. Several files keep their order (at the start or after the current page the last file goes in first). Change: build the pages with MuPDF (`extractPages`) and reload, like the other tools.
- **D2 Other tools through MuPDF, then reload.** Watermark, page numbers, header/footer, flatten, compress, password and bookmarks take the viewer's bytes (every change, `documents.download()`), run in the worker and come back as the same document (name, page and password kept). The viewer's history starts new; the notice row says `Verlauf nach Dokumentwerkzeug zurückgesetzt` (dismissable). Split and page images download files (one file, or a ZIP for several) and leave the document unchanged.
- **D3 Ranges and overlays ported from BentoPDF.** `pages.js` carries AGPL-3.0-only with the attribution line. Changes: open ranges (`8-`, `-3`), invalid parts are reported (the dialog marks the field instead of skipping them), German file names (`Plan_Seite-3.pdf`, `Plan_Seiten-1-3.pdf`, lists with commas), MuPDF instead of pdf-lib, text in Plex. `tests/spdx.test.js` accepts AGPL-3.0-only only with `// Ported from BentoPDF <path> at <commit>` on line 2.
- **D4 Overlays upright on rotated and cropped pages.** Text and images are placed in the page's visual coordinates (inverse page transform), and the old content is wrapped in `q … Q`, so an unbalanced graphics state in the page cannot move them.
- **D5 Compression.** Always lossless first (`garbage=4,compress,objstms`). Images are downsampled only on request (150 / 200 / 300 dpi), only 8-bit colour and grey images (1-bit scans, JBIG2 and masks stay), only above 1.25 × the target, to JPEG quality 75. The resolution is estimated against the size of the page the image is on (an image is never larger than its page), so it never becomes coarser than the target where it shows. The image keeps its object number (every page using it gets the smaller one) and its soft mask. The original is kept when the result is not smaller; a toast shows old and new size. The viewer's save keeps the compact file (scan fixture: 35.8 kB → 18.3 kB, saved 18.3 kB). Change: thresholds in `compress.js`.
- **D6 Encryption without object streams.** `Kennwort` writes AES-256 with the permissions in `/P`. Object streams are left out when encrypting: pdf-lib could not read MuPDF's encrypted object streams in the test. Commas in passwords are refused (MuPDF's option string uses them as separators). The viewer reopens the result with the new open password; its incremental save keeps the encryption (checked: the saved file needs the password in MuPDF).
- **D7 Password of the open file.** The viewer asks for the password itself and does not hand it to the page. A document tool that needs it gets `password` from the worker and asks once (`Kennwort` dialog, marked when wrong). The page keeps it in memory for this document only.
- **D8 Repair on open.** When the viewer cannot open a file, the worker reads it with MuPDF (which rebuilds a broken xref table) and writes it new; the viewer opens that copy and the notice row shows `PDF repariert` (warning, the file counts as changed). A file MuPDF cannot read either stays `PDF nicht lesbar`.
- **D9 Bookmarks through MuPDF, properties through the viewer.** The viewer build has no bookmark editing (only engine functions without API), so `Lesezeichen` reads and writes the outline in the worker (rows with title, page and level; indent, outdent, remove, add for the current page) and reloads. `Eigenschaften` uses the viewer's metadata plugin (title, author, subject, keywords) without a reload; the change is part of the next save.
- **D10 Cancel.** The running tool shows in the notice row with an `Abbrechen` action. Loops (split, page images, compress) stop between steps; one long MuPDF call cannot stop, so the worker is replaced when it has not answered after 1.5 s.
- **D11 Last options per visit.** Each dialog starts from the options of its last run in this visit (memory only, no files). The settings draft stays small.
- **D12 Placeholders as suggestions.** `{datei}`, `{datum}`, `{n}`, `{total}` and the number formats are offered as input suggestions (datalist), not explained in the dialog (DESIGN.md); the method doc lists them. `{datum}` uses the settings' date format.
- **D13 Menu icons.** Existing line icons: merge, split, stamp (watermark), number, pages (header/footer), image, upload (images as pages), layers (flatten), compress, lock, bookmark, file (properties), plus (new document), settings after a separator. OCR gets `ocr` in stage 5.
- **D14 Images as pages.** Images keep their pixels (no new encoding). `Bildgrösse` uses the image's own resolution (96 dpi when it has none); A4 and A3 fit the image inside the margin, `Automatisch` turns wide images to landscape. Without an open document the result opens as a new one, named after the first image.

## Stage 5: OCR

- **O1 tesseract.js 7.0.0 with core 7.0.0.** tesseract.js 7 needs core 7 (`^7.0.0`), which npm does not tag `latest` (that is 6.1.2); the script checks the dependency. Vendored: `tesseract.esm.min.js` and `worker.min.js` (with their third-party notices), the two LSTM cores with inlined WebAssembly (`tesseract-core-simd-lstm.wasm.js`, `tesseract-core-lstm.wasm.js`), no source maps. Total 10.8 MB.
- **O2 Core chosen by the page, relaxed SIMD left out.** tesseract.js 7 would pick a relaxed-SIMD core on browsers that support it, a third 3.9 MB file. `ocr.js` passes the core file itself (SIMD probe with `WebAssembly.validate`, else the plain core), as the plan names SIMD and non-SIMD. Change: vendor `tesseract-core-relaxedsimd-lstm.wasm.js` and pass the folder as `corePath`.
- **O3 Models from tessdata_fast, gzipped.** As the plan says, `deu` and `eng` come from `tesseract-ocr/tessdata_fast` tag 4.1.0 (commit pinned, SHA-256 checked; GitHub has no registry hash). They are stored as `.traineddata.gz` (deu 0.85 MB, eng 1.96 MB; tesseract.js unpacks them). The npm packages `@tesseract.js-data/*` hold only `best_int` and legacy models. Change: constant `TESSDATA` in `scripts/vendor-tesseract.mjs`.
- **O4 tesseract.js nested in the editor's worker.** `ocr.js` imports tesseract.js with `await import()` in the editor's worker; tesseract.js starts its own classic worker there (nested workers: Chromium, Firefox, Safari 15.5+). It ends after each OCR run to free its memory; the next run loads it again (from the browser cache). `cacheMethod: 'none'`: the models are site files, a second copy in IndexedDB is not needed.
- **O5 hOCR without DOMParser.** A worker has no DOMParser, so `parseHocr` reads tesseract's hOCR (regular, generated XHTML) with regular expressions: page, line classes (`ocr_line`, `ocr_textfloat`, `ocr_header`, `ocr_caption`), words, `bbox`, `baseline`, `textangle`, entities.
- **O6 Words stretched with Tz.** The plan's horizontal scaling: each word keeps the line's font size (baseline to line top, BentoPDF's rule) and is stretched to its box with `Tz`, so selection boxes keep one height per line. Gaps between words get a stretched space, so copied text and search across words work (`Revision B Zuluft 250`).
- **O7 Pages without text by default.** The dialog starts with `Ohne Text` (pages from which MuPDF extracts no text), so a second run does not add a second layer. `Alle`, `Aktuelle Seite` and `Bereich` read the chosen pages even when they have text.
- **O8 Rendering.** Grey, 300 dpi, the page as shown (rotation, crop box, annotations), at most 40 Mpx (an A0 plan at 300 dpi would need 139 Mpx in tesseract's WebAssembly memory). Page segmentation 3 (automatic, as the tesseract command line); tesseract.js would default to 6 (one block), which misses text spread over a plan.
- **O9 Node test without tesseract.js.** tesseract.js needs a browser worker, so `tests/helpers/tesseract-node.js` runs the same vendored core and models directly (TessBaseAPI: Init, SetImageFile, Recognize, GetHOCRText) with the same settings. `pdf-editor.ocr.test.js` skips with a message when the files are missing. The browser path was checked by hand (also under the sub-path): the scan fixture gets 5 words and the viewer's search finds and highlights `Zuluft` on the image.

## Stage 6: autosave

- **A1 Two object stores.** Slot data (`meta`) and the PDF bytes (`bytes`) are kept apart, so listing the slots (page start, each write) does not read three PDFs into memory.
- **A2 Slot identity is the file as opened.** Name + size of the opened file (the plan's rule), kept through document tools, repair and restore; so the same file opened again finds its slot.
- **A3 A found slot waits for a decision.** When a file with a slot opens, the slot is not overwritten by the new session's autosave until the user restores or discards it; otherwise opening the original again would destroy the unsaved work in the next 2 s. The new edits are not autosaved meanwhile (the notice is visible). Change: drop `app.pending` in `app.js`.
- **A4 What counts as a change.** The bridge's change events (annotations, form, pages, metadata, page scale) and document tools; the viewer's own unsaved flag is ignored (it does not reset when the page saves), and events while a file opens are ignored.
- **A5 Saving clears the slot.** Saving cannot know whether the browser really stored the download; the slot is removed when the download starts (the saved file is the newer state).
- **A6 Notices with two actions.** The plan wants restore and discard icons in the notice row. `lib/core/issues.js` takes `actions` (a list of `{ icon, label, run }`) besides `action`; other tools are unchanged. Restore uses ↶, discard the trash icon. The notice is a warning (unsaved work), with file name, date (settings format) and time.
- **A7 Flush on hide.** A waiting write runs at once when another file opens or the page is hidden (`visibilitychange`), so closing the tab right after an edit keeps it in most browsers; `beforeunload` prompts are not used (autosave replaces them).
